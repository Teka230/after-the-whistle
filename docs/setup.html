Déployer puis connecter l’app

La démo du site fonctionne sans serveur. Le widget ChatGPT réel nécessite le serveur MCP public déployé depuis le Blueprint Render.

Dans Render, crée un Blueprint depuis ce dépôt. Le service écoute sur le port fourni par l’hébergeur et expose le MCP sous /whistle/mcp.

  1. Déployer render.yaml depuis le dépôt GitHub.
  2. Attendre que le health check /whistle/ passe.
  3. Enregistrer https://<service>.onrender.com/whistle/mcp dans le connecteur ChatGPT.

Le stockage SQLite est un cache temporaire. Les données de match sont rechargées si le service redémarre.

git clone https://github.com/Teka230/after-the-whistle.git
cd after-the-whistle
pnpm install
pnpm run ingest:demo   # optionnel: seed offline
pnpm run up
pnpm run up:status

Endpoint local: http://127.0.0.1:8788/mcp. En dev foreground: pnpm dev:mcp.

# Render deployment
MCP_BASE_PATH=/whistle
AFTER_THE_WHISTLE_DB_PATH=/tmp/after-the-whistle.db
# PORT and RENDER_EXTERNAL_HOSTNAME are set by Render

Les connecteurs de données NBA et football sont des services externes; leur disponibilité et leur couverture peuvent varier. DEBRIEF_DB_PATH reste accepté comme alias local.

Démo et service réel

1
Site public

Le simulateur utilise des données d’exemple locales au navigateur; aucun appel MCP ou LLM.

2
Serveur MCP

Le service hébergé charge les matchs et sert le widget interactif dans ChatGPT.

3
Connecteur

Le lien de connexion dépend du nom attribué au service Render lors du déploiement.

Le service MCP public et le simulateur statique sont deux parcours distincts.
